# 实验前固定计划

在实现与计时前于 2026-09-27（Asia/Shanghai）固定。

我选择 BranchSafe KV，研究一个明确的系统问题：前缀共享能否减少分支管理复制，同时在事务失败和资源耗尽时保持父分支的所有可见字节不变？

候选比较：投机解码依赖草稿模型质量与成本匹配、实验较重；有限状态 token mask 已有成熟的原生高性能实现；事务式 KV 分支存储有可测 CPU 内存瓶颈与可验证生命周期不变量。第三项适合本机 16 GiB Apple M1 Pro。

贡献：独立实现有界页池、版本化序列写凭证、失败原子的追加预留、分支事务与可审计评测。分页、引用计数和写时复制都是已有方法，不主张算法原创。不包括生产 vLLM 集成、GPU 算子、训练或服务集群，不主张普遍加速。

## Target（计时前固定）
- 主要目标：在前缀=2048、分支=8、追加=16、接受=8、形状=(4层,4个KV头,64维)、float32、页大小16时，分支管理中位延迟相对预分配 dense-copy 基线至少提升2.0倍。
- 同一场景峰值受管 KV 数据字节不超过 dense 基线30%。指标是分配器所持数组 nbytes，不是RSS。
- 所有工作负载与测试的K/V逐位相等。预训练模型 logits 最大绝对误差<=1e-5，贪心token ID相同。
- 非法输入、容量失败、回滚、过期写凭证及重复清理不改变父状态、不泄漏存活页。

## 方法
Dense基线预分配容量，fork只复制已用前缀；eager-paged消融复制页；shared-paged共享引用，追加共享末页时COW。数据类型、输入、最终接受长度与单线程条件一致。初始化/预载单独测量；预热3次，每方法21次测量；固定随机种子随机打乱方法顺序，不删除离群点。报告中位数、IQR、原始样本和操作吞吐，不以21次样本推断p99。分别测分支管理与管理加所有分支materialize。输入生成和模型加载不计入相应计时间隔；追加校验、分配、fork、truncate、release和commit计入对应路径。原始结果含revision、源码哈希、环境和失败状态。

场景：短前缀(32,1分支)、中等(256,4)、主要(2048,8)、长前缀(4096,4)、非整页(2047,8)、无共享(0,8)、频繁读取(2048,8)。边界覆盖空token、页边界、容量耗尽、NaN/Inf、嵌套fork和并发过期写。Gaussian合成数据明确标记；可选真实预训练GPT-2验证单列，不作为生产推理耗时。

Expected：dense fork为O(LHDT)，共享fork为O(ceil(T/P))元数据；共享追加至多复制一个末页及新token。连续读取仍为O(LHDT)，可能抵消收益。性能目标是假设，不是实测成果。
